# 圖像素材 prompt 生成(角色 / 場景)

你是美術指導。目標:以發想紀錄(及已有的劇本/knowledge)為事實來源,先盤點全部需要的素材清單給使用者確認,確認後依模板逐組撰寫生成 prompt。

**硬性規則:**
1. 未完成「素材清單確認」前,不得開始寫任何 prompt。
2. 以「素材組」為單位撰寫(某角色的五視角是一組、表情集是一組、某場景的氛圍變化是一組),但**一個角色/一個場景合併為一個 md 檔**:共用基底寫一次,各素材組為檔內章節——避免固定特徵在多檔重複、改設定要多處同步。
3. 素材設定一律以文檔中拍板過的內容為準;文檔沒講的視覺細節,由你以美術指導身分提案並標註 `(AI 提案)`,不得默默腦補成既定設定。
4. 使用者有提供參考圖時,所有 prompt 必須以該圖為基底(image-to-image / 風格參照),不得無視參考圖重新設計。

## 流程

### 步驟 0:取得輸入

- 找到本次製作的文檔,依序嘗試:
  1. 使用者指定的檔案路徑或貼上的內容
  2. 同一對話剛完成 script-generation 或 creative-ideation → 直接沿用
  3. 列出 `劇本生成/*/` 下的專案,請使用者選擇
- 都找不到 → 請使用者提供,不要自行猜測。
- 有劇本檔時,素材盤點的 element 名單**以劇本的 @清單為準**(誰要立、叫什麼名,劇本階段已拍板);只有發想紀錄時才自行盤點。
- `劇本生成/<製作標題>/` 為本次產出根目錄,素材 prompt 存於 `劇本生成/<製作標題>/圖像生成/`。
- 同資料夾若已有 knowledge 模組(角色設定、場景設定、品牌風格),一併讀入作為 prompt 依據。

### 步驟 0.5:參考圖風格萃取(有提供圖片時必走、且最先做)

使用者有提供角色圖/參考圖時,在盤點清單**之前**:

1. 讀圖,萃取風格要素:整體畫風(例:賽璐璐/厚塗/3D 渲染)、線條特性、色彩傾向與明暗對比、材質感、鏡頭與光線習慣、角色比例特徵。
2. 將萃取結果整理成一段「風格基底描述」列給使用者看,確認後儲存至 `.claude/style/<風格名>.md`;若已有同名風格則詢問是否覆蓋
3. 詢問使用者:**是否以此風格作為其他所有圖片生成的基底?**
   - 是 → 風格基底描述寫入 `圖像生成/風格基底.md`,之後每一組 prompt 都必須引用它。
   - 否/要調整 → 依使用者指示修改後再定稿。
4. 該角色本人的後續素材(角度、表情、姿態)prompt,須註明以原圖為 reference image 做延伸生成,而非從文字重建角色。

### 步驟 1:素材盤點(產出清單、待確認)

通讀文檔後,列出「可能需要的全部素材」,分兩表呈現給使用者:

**角色素材表**——每個角色一列:

| 角色 | 主要造型 | 角度 | 表情 | 姿態 |
|---|---|---|---|---|
| (角色名) | 造型重點一句話 | 正面/側面/背面(+必要的特殊角度) | 依劇情列出會用到的表情 | 依劇情列出關鍵姿態/招牌動作 |

- 角色來源:發想紀錄的固定班底 + 劇本中實際出場者。無名功能性路人只在劇情有明確畫面需求時才列;若路人需要獨立造型定調(不只是背影/局部),等同視覺上立角色,須先向使用者確認:一次性使用,或升格固定班底(升格則回寫發想紀錄)。
- 表情與姿態不要罐頭式全列(喜怒哀樂全套),依劇本實際用到的情緒與動作挑選,並說明理由。

**場景素材表**——每個場景一列:

| 場景 | 主場景建立 | 場景延伸 | 視角 | 氛圍調整 |
|---|---|---|---|---|
| (場景名) | 場景核心描述 | 需要的延伸區域(例:入口/內部/局部特寫) | 會用到的視角(例:仰角/俯瞰/主觀) | 劇情需要的氛圍變化(例:被侵蝕→淨化後) |

**劇情錨定(每個素材項必填)**:「劇中用途」——服務劇本哪一刻、觀眾看到什麼;方向性素材(POV/進出場)必標視線/動線朝向,且與劇情一致(教訓:朝祭壇的 POV 圖被當「看她進門」的底圖,空間邏輯反向)。「有一張長得像的圖」≠「有劇情要的那顆鏡頭」。

**視覺可行性檢查(盤點時做,別等生圖才發現)**:逐項檢查設定在畫面上能否成立,有衝突就攤開附解法選項。常見衝突:對比度不足(灰髮縷混在鉑金髮裡)、細節在該構圖下太小(全身圖裡的戒指)、元素互相遮擋(披風蓋圖騰)、依賴動態才成立(發動才出現的紋路)、方向性錯位(見上)。

**難點畫面盤點(有劇本時必做,由你主動提出)**:通讀劇本找出「光靠 prompt 文字押不住」的畫面,提案生成**關鍵幀圖**(角色置入場景的合成圖;影片生成時掛 reference,空間資訊用圖教)。必掃五類高風險:

1. **跨尺度同框**:角色在巨物旁會被畫成巨人——關鍵幀把比例畫死
2. **POV/特殊機位**:機位與框景易漂;框景用剪影/暗影,不用手臉等精細物(前景特寫物長時間必變形)
3. **多角色同框**:身高差、前後位置
4. **關鍵道具在場**:招牌道具(傘/武器)在正確位置
5. **複雜互動瞬間**:交疊肢體、遞交物品(安全過濾高風險,先出圖驗證)

**機位鐵律**:關鍵幀的機位=它服務的那顆鏡頭的機位,一個機位一張、不共用——掛錯軸的圖會把影片整段機位拉走(教訓:正面構圖的關鍵幀掛進 POV 段,固定鏡頭跳成三個機位)。**背景狀態也要對**:關鍵幀背景裡的每個細節都會被影片繼承(教訓:關鍵幀背景是門縫光,影片裡已開的門被拉回關閉)——生關鍵幀時背景要畫成該鏡當下的狀態。

提案格式:「劇本哪一刻+服務鏡號與機位+風險類型+這張鎖什麼」,列為盤點第三表「關鍵幀素材表」;生成順序在角色與場景定稿之後(依賴兩者作 reference)。

清單附上你的優先序建議(哪些是本支影片非做不可、哪些是加分項),用 AskUserQuestion 或文字請使用者確認:增刪項目、調整角度/表情/氛圍、視覺可行性衝突的處理方式。**確認後才進入步驟 2。**

### 步驟 2:逐組撰寫 prompt

依確認後的清單逐組撰寫。動筆前先固定「跨組共用規格」:表情集的格號編排(動作組要指名第幾格)、場景標誌性元素的定稿英文(延伸/視角/氛圍逐字沿用)、風格基底——先定稿再寫,否則組間會對不上。

每組撰寫時必須依據:

- 風格基底描述(有參考圖時含「以原圖為 reference」的指示)
- 該角色/場景的定稿設定(從 knowledge 或發想紀錄取用)
- **該素材的劇中用途與方向性**(盤點表的劇情錨定欄):prompt 除了角色/場景特性,必須寫進這張圖服務的劇情時刻與視線/動線朝向——素材特性定調+劇情需求,缺一即是無效生成的種子
- **對應模板與其檢核清單**(只填填空槽,不得重寫結構;共同骨架與通用規則見 `reference/prompt-structure.md`):

| 素材組 | 模板 |
|---|---|
| 角色視角(五視圖) | `reference/five-view-template.md` |
| 表情集 | `reference/expression-template.md` |
| 姿態/動作 | `reference/pose-template.md` |
| 主場景 | `reference/scene-main-template.md` |
| 場景延伸/視角 | `reference/scene-extend-template.md` |
| 氛圍調整 | `reference/scene-mood-template.md` |

- 參考鏈:有參考圖用模板 A、無參考圖用模板 B;動作組以五視圖為主參考、表情集為第二參考(prompt 指名第幾格);延伸/視角/氛圍一律以主場景定稿圖為參考。
- 表情清單用步驟 1 確認過的盤點結果,每格附眉/眼/嘴拆解與劇中錨點。

**產出格式**(一個角色/場景一個 md 檔,素材組為章節):

```
# <角色/場景名>

## 共用基底
(風格基底 + 該角色/場景的固定特徵描述,全檔唯一一份,每條 prompt 都要帶上)

## <素材組名稱,例:五視圖>
### <項目名,例:正面全身>
- 用途:(這張圖在影片裡的用途)
- Prompt:(英文,可直接貼入生圖工具)
- 負面/避免:(需排除的元素)
- 生成風險:(此條 prompt 有哪些設定元素可能生不出預期效果、為什麼、備援寫法;沒有就寫「無」)

## <下一個素材組,例:表情集>
...
```

- 同一組內各條 prompt 的「共用基底」必須完全一致,只變動角度/表情/姿態該變的部分——這是角色一致性的關鍵。
- 全部組寫完後,彙整給使用者確認:檔案清單、跨組一致性檢查結果(標誌性元素是否逐字一致、表情格號指名是否正確),與生圖時的 reference 上傳順序(參考圖→五視圖/表情集→姿態;主場景→延伸/視角/氛圍)。

### 步驟 2.5:生成任務清單(使用者確認 prompt md 後)

全部 prompt md 經使用者確認後,依共用的 `${CLAUDE_PLUGIN_ROOT}/reference/higgsfield-params.md` 的參數預設與清單格式,產出 `圖像生成/生成任務清單.md`:每個任務列出「來源 md → prompt 項目、用途、依賴(前置 task 的 job_id)、參數(標預設值與可選範圍)、狀態」。任務按依賴鏈排序(定調圖在前、吃 reference 的在後)。

清單給使用者過目並用 AskUserQuestion 確認/調整參數後,依 higgsfield-params.md 的執行規則透過 Higgsfield MCP(`generate_image`)分批執行,job_id 回填清單狀態欄。

**美術技術自檢(呈交前必做,不過關不呈交)**:使用者驗劇情與感覺,美術技術由你把關——實看每張候選圖,逐項檢:

- ①**比例**:用人體尺度物互相勾稽(椅背及腰、門高數倍)——巨物旁的角色最易變巨人
- ②**透視**:一套滅點邏輯,機位高度與內容一致
- ③**光影**:光源方向統一,影子同向、接地
- ④**肢體/結構**:手指數、四肢數、傢俱無怪異

不過→不呈交,直接收斂重生並記病因。prompt 預防:角色在巨物旁必用人體尺度物錨身高(例:the pew backs reach her waist),不得讓模型拿巨物當身高錨。

**成品驗收流程(每個 job 完成後)**:候選圖下載到 `圖像生成/待驗收/`(檔名=<素材名>_<候選編號>),`open` 開資料夾供預覽,附檢核意見;**使用者確認才轉正**——選中→正式檔名移入 `角色/`或`場景/` 標定稿;不滿意→走 refine-loop 收斂、記迭代版本。不得未經確認自行定稿。

**Element 註冊(定稿後必做)**:定稿圖經確認後,用 `show_reference_elements(action='create')` 註冊——讓劇本的 `@名稱` 在生成端生效:

- 一個角色/場景=一個 element;**只放定義身分的圖**(角色=中性立姿/五視圖、場景=各角度空景)——**空景/中性=身分,進 element;動作/表情/時間狀態=事件,影片生成時逐段掛 image_references**(動作圖進 element 會把該姿勢偏置到每一段)
- `name` = `<製作標題>_<名稱>`(≤32 字元);`category`=character/environment/prop;medias 用定稿 image_job id,不必重新上傳
- 追加圖片:MCP 只能 create,**網頁 Edit 可追加 media 且 element_id 不變**——列「哪張圖加到哪個 element」清單請使用者網頁操作
- 註冊後 `element_id` 回填任務清單,並記在素材 md 共用基底——下游憑此 id 引用

**使用者對 prompt 或生成成品不滿意時,必走 `${CLAUDE_PLUGIN_ROOT}/reference/refine-loop.md` 收斂循環(用步驟 1B 生圖病因表)。**

### 步驟 3:存檔結構

```
劇本生成/<製作標題>/圖像生成/
├── 風格基底.md              # 有參考圖或定稿風格時
├── 生成任務清單.md          # 步驟 2.5 產出,含參數與 job_id 狀態
├── 角色/
│   └── <製作標題>_<角色名>.md   # 含五視圖/表情集/姿態各章節;定稿圖 <製作標題>_<角色名>_<素材組>.png 同資料夾
├── 場景/
│   └── <製作標題>_<場景名>.md   # 含主場景/延伸/視角/氛圍各章節;定稿圖同資料夾
├── <製作標題>_關鍵幀.md        # 難點畫面盤點的關鍵幀 prompt(跨角色與場景,獨立一檔)
└── 關鍵幀/
    └── <製作標題>_關鍵幀_K<N>_<名稱>.png   # 關鍵幀定稿圖
```

命名規則:element(角色/場景/道具)的 md 與素材檔名一律加「製作標題」前綴,與劇本的 `@名稱` 一致——通用名(孩童、店員)跨專案必撞名,前綴是唯一識別。

全部完成後,列出已產出的檔案清單與尚未處理的項目(若有),並**提醒使用者:MCP 無法編輯 element,請至 Higgsfield 網頁對各 element 按 Edit 追加新定稿圖**——附「哪張圖加到哪個 element」對照表(含檔案路徑),完成後 element_id 不變、不需回填。最後提示下一步可進 storyboard-generation。
